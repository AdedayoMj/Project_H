The files under `/app/input` define four independent field-season simulations. `manifest.json` has the exact object schema `{"schema_version": 1, "campaigns": [{"campaign_id": string, "directory": absolute-path}, ...]}`. Campaigns are listed in bytewise ascending `campaign_id` order. Each campaign directory contains `job_ticket.json`, `field_boundary.geojson`, `soil_map_units.geojson`, `soil_horizons.csv`, `vegetation_index.csv`, `weather.csv`, `initial_depletion.csv`, and `irrigation_events.geojson`. Dates are ISO 8601 civil dates and simulation endpoints are inclusive. All coordinates are already in the metre-based projected CRS named by the ticket; no reprojection is required.

The job ticket has keys `campaign_id`, `crs`, `grid`, `simulation`, `crop`, `irrigation`, and `management_zone_edges_mm`. `grid` contains `origin_x`, `origin_y`, `cell_width_m`, `cell_height_m`, `row_direction`, and `column_direction`; directions are always `north_to_south` and `west_to_east`. For zero-based row $r$ and column $c$, the closed grid cell spans $[origin_x+c w, origin_x+(c+1)w]$ in x and $[origin_y-(r+1)h, origin_y-rh]$ in y. Consider only rows and columns whose cells meet the field envelope. A cell becomes an analysis unit exactly when its polygon intersection with the field geometry has positive area. Its geometry is that intersection, its identifier is `r{row:04d}c{column:04d}`, and its `area_fraction` is clipped area divided by field area. Boundary rings and holes use ordinary GeoJSON Polygon semantics. Geometry calculations use the coordinates as written; do not snap, buffer, simplify, or use a centroid inclusion rule.

`soil_map_units.geojson` is a FeatureCollection whose polygon features have the sole property `map_unit_id`. The polygons form a non-overlapping partition covering the field. `soil_horizons.csv` has the exact header `map_unit_id,top_cm,bottom_cm,theta_fc,theta_wp`; intervals are top-inclusive and bottom-exclusive. For the fixed rooting depth $Z_r$ from `crop.root_depth_m`, a map unit's storage is the sum over horizons of $10(\theta_{FC}-\theta_{WP})$ times the horizon thickness in centimetres intersecting $[0,100Z_r)$. An analysis unit's $TAW$ is the intersection-area-weighted mean of the map-unit storages over its clipped geometry, and $RAW=p\,TAW$ using `crop.depletion_fraction`. The horizon table completely covers every root zone.

`initial_depletion.csv` has the exact header `unit_id,depletion_fraction` and one row per analysis unit. Initial depletion is that fraction times the unit's TAW. `vegetation_index.csv` has the exact header `unit_id,date,vi` and at least two strictly increasing observations for every unit. For each simulation day, VI is linearly interpolated in ordinal-day space between bracketing observations, with the first or last observation held outside its observed range. Daily $K_c$ is $clip(a\,VI+b,Kc_{min},Kc_{max})$ using the four values in `crop`.

`weather.csv` has the exact header `date,eto_mm,effective_precipitation_mm` and exactly one row for every simulation date. `irrigation_events.geojson` contains polygon features with the exact properties `event_id`, `date`, and `gross_depth_mm`. For an analysis unit and event, covered gross depth is the event's gross depth multiplied by `area(unit geometry intersect event geometry) / area(unit geometry)`. Sum all same-day event contributions, including overlapping footprints, then multiply by `irrigation.efficiency` to obtain that day's effective irrigation. Events outside the unit contribute zero.

The authoritative daily model is the FAO-56 single crop-coefficient balance. Let $D$ be depletion at the end of the previous day. The day's stress coefficient is $K_s=1$ when $D\le RAW$, otherwise $clip((TAW-D)/(TAW-RAW),0,1)$. Crop evapotranspiration is $ET_c=K_sK_cET_o$. Let $q=D+ET_c-P_{eff}-I_{eff}$. The day's drainage is $max(0,-q)$ and its final depletion is $clip(q,0,TAW)$. Advance days chronologically without intermediate rounding. Accumulate `seasonal_etc_mm`, `seasonal_effective_irrigation_mm`, `seasonal_drainage_mm`, `stress_days` (the integer count of days with $K_s<1$), and `minimum_ks`. The final crop coefficient is the coefficient on the inclusive end date.

If final depletion is at most RAW, recommended gross irrigation is zero. Otherwise it is `min(irrigation.max_application_mm, final_depletion / irrigation.efficiency)`. Assign the unrounded recommendation to the half-open bands defined by the increasing `management_zone_edges_mm`, which is `[0,10,20,30]`: `Z0` is $[0,10)$, `Z1` is $[10,20)$, `Z2` is $[20,30)$, and `Z3` is $[30,+\infty)$. A boundary value belongs to the higher zone.

`/app/output/prescription.geojson` must be a GeoJSON FeatureCollection with exact top-level keys `type` and `features`. Each feature has exact keys `type`, `geometry`, and `properties`, uses type `Feature`, and has the clipped analysis-unit geometry. Its properties have exactly these keys and types: `campaign_id` string, `unit_id` string, `row` integer, `column` integer, `zone_id` string, and finite JSON numbers `clipped_area_m2`, `area_fraction`, `taw_mm`, `raw_mm`, `final_dr_mm`, `final_kc`, `recommended_gross_mm`, `seasonal_etc_mm`, `seasonal_effective_irrigation_mm`, `seasonal_drainage_mm`, `minimum_ks`, plus integer `stress_days`. Features are ordered by bytewise `campaign_id`, then integer row, then integer column.

`/app/output/units.csv` has exactly the same records and order as the GeoJSON properties, with this exact header: `campaign_id,unit_id,row,column,zone_id,clipped_area_m2,area_fraction,taw_mm,raw_mm,final_dr_mm,final_kc,recommended_gross_mm,seasonal_etc_mm,seasonal_effective_irrigation_mm,seasonal_drainage_mm,stress_days,minimum_ks`. Integer fields use base-ten integer text and all other numeric fields use finite decimal text.

`/app/output/summary.json` has exact top-level keys `schema_version` and `campaigns`, with schema version 1. Campaigns are in bytewise identifier order. Each record has exact keys `campaign_id`, `analysis_unit_count`, `field_area_m2`, `irrigated_area_m2`, `area_weighted_mean_depth_mm`, `total_gross_volume_m3`, and `zones`. `analysis_unit_count` is an integer; other scalar metrics are finite numbers. `irrigated_area_m2` sums areas whose unrounded recommendation is positive. Mean depth is $\sum(area\times depth)/field\ area$ and volume is $\sum(area\times depth)/1000$. `zones` is a four-item list ordered `Z0` through `Z3`; every entry has exact keys `zone_id`, `unit_count`, `area_m2`, `area_fraction`, and `mean_depth_mm`, where the mean is area-weighted within the zone and is zero only for an empty zone.
