Audit the opening decision frontier of every Sokoban board in `/app/input/puzzles/`. This is a counterfactual analysis, not a request for only one best solution. For each board, enumerate every first-push commitment the player can make: a box's zero-based starting row and column plus a push direction. A commitment belongs in the frontier exactly when the push destination is empty floor or goal and the player can reach the required standing cell from the initial position without moving any box. Legal first pushes that make the remaining puzzle unsolvable must still be reported. Do not modify `/app/input/`; `/app/input/rules.json` is normative for the complete contract.

For every solvable commitment, optimize complete move strings constrained to make that commitment their first push. The walk used to approach the box is not fixed. Compare completions by four priorities: minimum total player moves; then minimum pushes; then minimum changes between consecutive push directions; then the lexicographically smallest complete move string under `D < L < R < U`. Count every distinct complete move string tied on the first three priorities modulo `1000000007`. The first push contributes zero direction changes; each later push contributes one exactly when its direction differs from the preceding push direction. Different shortest walks to the committed box are distinct strings and contribute separately to the count.

For a puzzle, `minimum_moves` is the smallest `conditional_moves` among its solvable commitments. A solvable commitment's `move_regret` is `conditional_moves - minimum_moves`, so every globally move-optimal opening has regret zero. Its `canonical_completion` is the full move string from the original player position, including the setup walk and committed first push. It must legally solve the board and its first push must use the reported box and direction.

Write `/app/output/first_push_frontier.json` with exactly the top-level keys `schema_version` and `puzzles`. `schema_version` is integer `2`. `puzzles` contains exactly one record per published puzzle in ascending `puzzle_id` order, with exactly `puzzle_id`, `minimum_moves`, and `commitments`. Sort `commitments` by `box_row`, then `box_column`, then direction under `D < L < R < U`.

Each commitment contains exactly `box_row`, `box_column`, `direction`, `solvable`, `conditional_moves`, `move_regret`, `conditional_pushes`, `conditional_push_direction_changes`, `optimal_completion_count_mod`, and `canonical_completion`. For a solvable commitment, the five numeric result fields are nonnegative integers, the count is in `0..1000000006`, and `canonical_completion` is a nonempty uppercase `U`/`D`/`L`/`R` string. For an unsolvable commitment, `canonical_completion`, `conditional_moves`, `move_regret`, `conditional_pushes`, and `conditional_push_direction_changes` are JSON `null`, while `optimal_completion_count_mod` is integer `0`.

Movement uses the usual published rules: `U` decreases the row, `D` increases it, `L` decreases the column, and `R` increases it. Stepping into a box pushes it one cell in the same direction only when the destination is free. Walls, the grid boundary, and a second box obstruct movement. A completion solves the board when every box occupies a goal.

The fixture deliberately contains globally optimal openings, positive-regret openings, and legal deadlocking openings. Verification independently derives the complete initial frontier, replays every submitted completion, confirms its committed first push, and checks all hidden conditional optima, canonical representatives, regrets, and modular counts. Omitting a reachable commitment or adding an unreachable one fails.
