Solve every Sokoban instance published under `/app/input/puzzles/` by reporting both its unique canonical optimum and the number of tied optima. `/app/input/rules.json` is normative: it defines the board glyphs, move semantics, optimization order, instance bounds, counting rule, and exact output schema. Do not modify anything under `/app/input/`.

Solutions are ordered by three exact priorities. First, minimize total player moves: the number of characters in the move string, counting every step whether or not it pushes a box. Second, among move-optimal solutions, minimize pushes. Third, among solutions tied on moves and pushes, choose the lexicographically smallest complete move string using the explicit character order `D < L < R < U`. All three levels are mandatory; an alternative shortest solution fails even when it is legal. Also count all distinct complete move strings tied on the first two priorities and report that count modulo `1000000007`; two solutions are distinct exactly when their move strings differ at one or more character positions.

Write `/app/output/solutions.json` containing exactly the keys `schema_version` and `solutions`. `schema_version` is the integer 1. `solutions` is an array holding exactly one record per published puzzle, ordered ascending by `puzzle_id`, where each record has exactly the keys `puzzle_id`, `moves`, and `optimal_solution_count_mod`. `moves` is a string over the uppercase characters `U`, `D`, `L`, and `R` with one character per player step and no separators, whitespace, or lowercase. `optimal_solution_count_mod` is an integer from `0` through `1000000006` containing the required count modulo `1000000007`.

`U` decreases the row, `D` increases the row, `L` decreases the column, `R` increases the column. Stepping into a box pushes it one cell in the same direction; the destination must be floor or goal and must not hold another box. Walking into a wall, pushing into a wall, pushing into a second box, or leaving the grid is illegal. A puzzle is solved when every box occupies a goal.

Every instance was generated backwards from its solved state, so a legal solution is guaranteed to exist, and the reference solver proved each canonical optimum and tied-solution count inside the expansion envelope published in `rules.json`. Verification independently replays each submitted move string, checks its hidden optimal move and push counts, checks the canonical move-string tie-break, and checks the reported modular count; every puzzle must pass. This is an exact enumeration task as well as an optimal-path task: omitting `optimal_solution_count_mod` fails even when `moves` is the canonical optimum.
